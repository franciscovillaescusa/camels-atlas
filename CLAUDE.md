# CAMELS Literature Atlas — notes for Claude

The site is `index.html`, generated by `build_camels_atlas.py` from `atlas.html`, `atlas.css`, `atlas.js`
and the data files. Never edit `index.html` by hand. A GitHub job rebuilds it on the 1st and 15th of each
month and opens an issue titled "New papers need tags" when new papers are not tagged yet.

## Tagging new papers ("tag the new papers")

1. `git pull` (the job may have pushed new papers).
2. `python3 build_camels_atlas.py --offline` (refreshes `index.html` from the cache if needed; if
   `atlas_cache/` is missing, run without `--offline`).
3. `python3 tagging.py list` — shows each untagged paper (title, abstract) and the allowed tag names.
4. Read each abstract and add an entry to `atlas_tags.json`, keyed by the paper ID:
   `{"title": ..., "suite": [...], "data": [...], "method": [...], "uncertain": [...]}`.
   Use only the allowed names. Put a tag in `"uncertain"` when the abstract does not state it clearly.
   For papers without an abstract, tag from the title, mark all tags uncertain and add
   `"note": "No abstract available: tags guessed from the title only; please check."`.
   Conventions: "CAMELS (suite not stated)" when no suite is named; "Non-CAMELS simulations" when other
   simulations are also used; "No ML" for papers without machine learning.
5. `python3 tagging.py unassigned` — if a paper in "Unassigned (new papers)" clearly fits a topic, propose it
   to the user and, if they agree, add `{"topic": "<exact topic name>"}` for it to `atlas_overrides.json`.
6. Rebuild and test:
   `python3 build_camels_atlas.py --offline && python3 validate_atlas.py && python3 check_atlas.py --chrome`
   (`check_atlas.py` needs `pip install playwright`).
7. Show the user the tags you assigned, then commit (`atlas_tags.json`, `atlas_overrides.json`,
   `index.html`, `atlas_positions.json`, `preview.png`) and push.
8. Close the open "New papers need tags" issue: `gh issue close <number> -c "Tagged in <commit>"`.

## Other notes

- Hand corrections go in `atlas_overrides.json`, not in code. Topics of existing papers are fixed in
  `TOPIC_SEED` (in the build script); `--recluster` would redo them and needs topic names reviewed.
- Layout positions are stored in `atlas_positions.json` so the maps stay stable; commit it with `index.html`.
- The ADS token is read from `~/.ads/dev_key` locally and from the `ADS_TOKEN` secret in GitHub.
